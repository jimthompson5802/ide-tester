## Technical approach and decisions to qualify

Use the existing launched `VSCodeIDE` instance to construct a separate
`EditorFiles` adapter; only the IDE adapter launches or closes processes.
Keep contracts, T02/T03 orchestration and disk verification platform-neutral.
Native imports and AX/keyboard operations stay behind isolated macOS workers.

Proposed revised contract in `adapters/base.py`:
`EditorFiles.new_document(*, deadline)`, `enter_text(text, *, deadline)` and
`save_as(path, *, deadline)`, plus a controlled
editor-interaction exception/reason set. These are design targets, not existing
APIs. Entry/Save As must revalidate the current untitled document and refuse
uncertain focus or identity. After saving, verify the exact destination is active.
Proposed `VSCodeEditorFiles(session)` in
`adapters/vscode_files.py` receives the same in-memory session; it cannot discover,
attach to, launch or close another instance. Add only the narrow session/backend
bridge needed to send owned editor requests; do not put file editing methods in
the public IDE protocol. Exact bridge and worker request names are frozen in P1-04.

Preferred investigation: owned-window AX commands or verified keyboard actions
to create an empty untitled editor, focus it, enter text, and Save As the exact
new destination. Qualify the owned Save dialog, destination and confirmation;
refuse unexpected dialogs and overwrite prompts.
Do not assume AX text is writable or infer full-path identity from a basename.
Qualify untitled-document/workspace identity and a focused editor independently
of sending New; qualify full saved-path identity after Save As.
Revalidate PID/birth/executable/launch arguments, owned window,
workspace, modal state and focused target before each mutating interaction.
Reacquire AX references per worker; never serialize native object handles.
Prefer a qualified action scoped to the owned process; if session-wide keyboard
events are needed, qualify foreground/focus checks immediately before input.
Focus loss stops actions. Residual focus races require explicit evidence and
developer acceptance at Phase 1; exclusive desktop use remains a prerequisite.
Avoid clipboard use and arbitrary UI-tree dumps.

Use deterministic text bytes `message = "edited by ide-smoke"\n` encoded
as UTF-8, with exact byte comparison. The new `created.py` destination must be
absent initially and can only be created through the IDE during the positive test.
The manager's existing `example.py` fixture is not the output. Disk verification
must not create, repair or rewrite the target. It runs outside `EditorFiles`.
Poll with monotonic deadlines until exact content appears; allow temporary
absence after Save As. Qualify and observe the untitled editor's entered text and
dirty state with destination absent before the explicit Save As action, then
independently verify exact persisted content. Correct
disk bytes alone must not pass when Auto Save could have masked a broken Save
interaction. Inspect relevant settings read-only; incompatible Auto Save settings
require a concrete developer setup decision before dependent host work. Sending
a keystroke alone is insufficient.

Proposed `verification.py::verify_saved_file()` safely reads only the fixed
`created.py` destination beneath the current manager-owned workspace with a
bounded regular-file read, no symlink following and
validated parent identity. Add a narrow manager read operation in `workspace.py`
if necessary to use its existing qualified descriptors; a persisted manifest is
not authority. Permit normal atomic-save replacement of the file inode while
rejecting directory replacement, symlinks, hard-link aliases and special files.
Never read an arbitrary resolved path outside the admitted fixture. For these
small fixtures, cap content at 4096 bytes plus one oversize-detection byte.
Missing/incorrect content after a qualified Save and completed persistence wait
is FAIL; unsafe paths, unreadable/unstable inspection, ambiguous UI, unexplained
timeouts and worker failures are HARNESS ERROR. Positively identified missing
host prerequisites are BLOCKED. Refine exact reason codes from Phase 1 evidence;
do not report a product failure when automation cannot establish the action.

Provide a typed allowlisted `file_verification` summary through
`OperationContext` and `run_attempt()`'s summary construction, validated by the
reporter. Proposed fields: test ID, fixed target basename, comparison mode,
expected byte count, bounded observed byte count, match boolean and controlled
status. Mark capped observations so they cannot be mistaken for a full-file
length. Omit actual text. Expose a short controlled mismatch explanation, byte
counts and saved evidence path in CLI output. Hashes, first-difference offsets,
extra mismatch categories, generic free-text payloads and screenshots are not
required.

T02 gets one deadline for New plus empty untitled-editor verification. T03 gets
one deadline shared by text entry, Save As, saved-path verification and disk polling. Initially reuse the
existing `ide_startup_seconds` per-operation budget already supplied for T02/T03;
document this explicitly without adding schema keys. Worker calls use remaining
time and existing caps. Do not retry mutating actions after uncertain completion.
Record polling/call bounds and existing synchronous-controller limitations.

Phase 1 must resolve untitled-document and saved-file predicates, input mechanism,
Save As dialog/confirmation evidence,
timeout/error mapping, any relevant accessibility/editor settings, and the exact
production seam. The M1-00 Chat-input setting finding is not proof that editor
editing requires the same setting. If a setting is required, record current
state read-only and request a concrete developer setup decision before dependent
host work; do not silently change persistent settings. Existing PyObjC wheels
are the starting point. Any proposed new dependency requires demonstrated need,
wheel-only qualification and a reviewed plan revision before installation.
