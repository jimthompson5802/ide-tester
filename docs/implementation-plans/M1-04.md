### Session boundary and ownership

Create these platform-neutral symbols in `src/ide_smoke/adapters/base.py`:

```python
class IDE(Protocol):
    @property
    def requires_workspace_retention(self) -> bool: ...
    def get_version(self, *, deadline: float) -> str: ...
    def launch(self, workspace: Path, *, deadline: float) -> None: ...
    def wait_ready(self, *, deadline: float) -> None: ...
    def close(self) -> None: ...
```

`deadline` is an absolute monotonic timestamp, not an additional timeout.
`get_version`, launch and readiness receive the same timestamp from T01.
`VSCodeIDE(executable: Path, profile_root: Path, *, _backend=None,
_clock=time.monotonic, _sleep=time.sleep)` in `adapters/vscode.py` implements the
controller lifecycle. It starts with no process and retention false. Entering
`launch` sets retention true **before calling any backend startup code**; it stays
true after failure, interruption or successful close. This conservatively covers
an interruption during process creation before handle assignment. It does not
claim that every attempted launch actually spawned a process.

Define `LifecycleReason` as a closed enum with the reasons in the result table
below, `LifecycleError(reason, *, stage=None)` for controlled failures, and
`CleanupError` for unconfirmed owned cleanup. CleanupError may carry only validated
local diagnostic attributes `owned_pid`, optional `owned_birth`, and `workspace`
from the current in-memory owner. No arbitrary native message becomes a public
reason. Diagnostic attributes are for local manual inspection only, never
recovery/deletion authority or additional summary fields.

The backend seam preserves the qualified `LaunchSpec`, `ProcessIdentity`,
`Observation` and `Backend.start(spec, deadline, claim)`, `observe(identity,
deadline)`, `close(identity, deadline)` behavior from the probe. Add private
`Backend.get_version(executable: Path, *, deadline: float) -> str` for the bounded
metadata seam shared by fake/native backends. The backend caches the validated
metadata with its selected executable identity; startup obtains it under the same
deadline if a direct API caller has not first requested the version. These are private
implementation/test seams in `adapters/vscode.py`; native backend code lives in
`platforms/macos/vscode_session.py`. `close()` supports never-started, partial,
ready, failed and already-closed states. Register it before version/launch work.
Retain a raw Popen immediately, defer SIGINT delivery only through its assignment,
and keep main-thread launch as the qualified constraint. No recovery retry,
foreign attachment, independently terminated helper or forced IDE kill is added.

### Native launch, identity and readiness

- Support only the metadata-selected native application executable. The qualified
  path is `/Applications/Visual Studio Code.app/Contents/MacOS/Code`, VS Code
  1.135.0. Validate `Contents/Info.plist` bundle `com.microsoft.VSCode`, matching
  `CFBundleExecutable`, executable access and native Mach-O header. This is not a
  code-signature check or qualification of every application build/CPU slice.
  Reject wrappers; preserve the executable already selected by admission.
- Construct exactly the current vector: native executable, `--user-data-dir`,
  admitted fixed user-data child, `--extensions-dir`, admitted fixed extensions
  child, `--new-window`, current manager-issued workspace. No shell, PATH
  reselection, copied authentication, persistent settings edit or launcher
  substitution. Discard application stdout/stderr in ordinary runs.
- Before spawn, require observed Accessibility trust and a visible graphical
  session. Inspect registered VS Code applications plus same-user processes
  matching the selected executable by canonical/file identity. Compare exact
  profile arguments, including aliases; uncertain/relative arguments fail closed.
  Occupied profile is BLOCKED before spawn. Registered alternate installations
  are inspected; **unregistered alternate installations are not comprehensively
  detected**. Exclusive profile reservation across installations remains a manual
  prerequisite; conflict checks do not establish exclusivity.
- The original Popen PID, kernel birth, executable and exact argv establish the
  owned identity. Recheck identity around AppKit lookup and immediately before
  native mutation; require direct controller parent and original session. PID
  reuse, identity disagreement or ambiguous ownership never permits termination.
  AppKit launch date is optional corroboration; when present, require a finite
  value within 0.001s of kernel birth. Missing registration is bounded progress,
  not permission to attach to a different application.
- Readiness requires the owned live application and exactly one associated
  workspace window: the workspace basename must be an exact title component
  split on ` — `, combined with the full exact workspace argument in process
  identity. AX does not independently provide a full workspace path here.
  Exhaust the AX traversal within 600 nodes and observe `AXWebArea`, `AXOutline`
  and `AXToolbar`; `AXTabGroup` is diagnostic only. Generic loading/welcome titles
  remain nonready. Wrong/ambiguous windows, modal/sheet/AXDialog and unrecognized
  AXSystemDialog cannot pass. Leave dialogs untouched.
- Request `AXManualAccessibility=True` only on the positively owned application,
  once after a successful acknowledgement per session. Do not repeatedly restart
  Electron's delayed exposure. Poll under the existing deadline, without a new
  fixed startup sleep or persistent `editor.accessibilitySupport` changes.

### Timing, worker and installed metadata

| Item | Fixed specification and qualification limit |
| --- | --- |
| Startup | T01 sets `deadline = monotonic() + config.ide_startup_seconds` before version/launch; all startup work shares it. Record total elapsed time even on failure/interruption. |

### Cleanup and unconditional GUI workspace retention

The accepted scope verifies exit of the original main process, current session
members and previously observed birth identities, including observed reparenting.
Unseen detached descendants and automatic recovery remain deferred future work.
Never label current tracking as complete ancestry coverage. Detected surviving
observed processes, identity uncertainty, termination refusal or deadline expiry
still cause CleanupError, nonzero exit and local owned-resource diagnostics.
Only the validated app-specific graceful quit is sent; retained processes are
not independently killed. No cleanup is reconstructed from saved artifacts.

**Phase 2 policy: retain every workspace whose session entered `launch`, even
when T01 and observed cleanup pass, regardless of `retain_on_failure`.** Preserve
the configured manifest value truthfully; this is an independent safety policy,
not a rewritten configuration or fabricated cleanup failure. Finalization order
remains: run operation cleanups, save initial manifest, decide disposition,
release manager resources, save final evidence, release guard. Stronger existing
ownership/evidence/cleanup-error retention reasons retain precedence; otherwise
use disposition `retained`, fixed reason `gui_exit_scope_limited`. Record the
existing WORKSPACE_RETAINED result/event; add no new report schema or configuration
key. Descriptor-qualified manager release still runs and errors still count.

The monotonic `requires_workspace_retention` property is the platform-neutral
signal read from `OperationContext.session` after cleanups. Reading it must
perform no I/O and return an actual bool. Invalid/throwing retention state fails
closed to retention plus controlled CLEANUP_FAILED, without bypassing descriptor
release, evidence persistence or guard release. Pure non-GUI and
private injected operations without a GUI session keep existing M1-03 removal/
configured-retention behavior. Retention alone changes neither T01, cleanup
outcome nor exit precedence. Do not delete current retained fixtures/profiles or
introduce stale-resource sweeps. This conservative policy is part of the Phase 1
package submitted for validation; no runtime behavior was changed in P1-04.
