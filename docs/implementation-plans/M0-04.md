## Technical approach

Reuse the installed prebuilt application if compatible and usable. Record its executable architecture using bundle metadata and `file`, and correlate the application with the CLI resolution and full version output. For this Apple Silicon host, prefer the existing compatible arm64 or Universal build; an unexpected architecture or different installation requires investigation before changing software.

Use the Command Palette PATH installation action only if fresh-terminal verification establishes that the CLI is unavailable. The official [macOS setup instructions](https://code.visualstudio.com/docs/setup/mac), consulted during planning, describe that action and restarting the terminal. Do not treat an absolute-path launch as satisfying the bare `code` resolution criterion. Do not replace a working installation merely to upgrade it. If no compatible usable application is available, record the finding and obtain a concrete developer decision before replacing an existing application; any needed installation must use an official compatible prebuilt distribution.

Use the available Python interpreter-selection UI with the explicit checkout `.venv/bin/python` path. If that UI is unavailable, defer editor selection and record why, as the acceptance criteria permit. No optional extension installation is needed for this plan. A later request to install one should be handled as an explicit scope decision. A settings entry alone is insufficient evidence that the editor selected the interpreter. Independent `.venv/bin/python` checks remain required even when selection is deferred.
