## Technical approach

Reuse the explicit Homebrew interpreter rather than relying on uv's minor-version interpreter discovery. Keep `.python-version` at `3.12` locally; it is a minor-version preference, not an exact lock or a guarantee of Homebrew selection. Always pass the selected interpreter path when creating `.venv`, then use `.venv/bin/python` explicitly. Record exact patch and architecture again at execution. An existing newer Homebrew 3.12.x patch is acceptable when provenance, arm64 architecture, and all verification checks pass; record the actual patch and resolved base path. A different minor version, architecture, provenance, older patch, or failed check requires developer resolution; never upgrade or download Python to satisfy this story.

One execution phase is sufficient: the remaining uncertainty is environment compatibility, established directly by creation and interpreter assertions. If the native terminal is unavailable to the implementing agent, prepare the bounded commands for the developer to run there and collect their output; do not treat an attempted architecture switch or agent Rosetta output as native-terminal evidence. Missing or incompatible prerequisites block creation rather than triggering an alternative installation.
