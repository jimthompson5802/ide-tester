## Proposed contracts and technical approach

All new paths, names, flags, schemas, and deadlines below are design targets until implemented. Phase 1 must refine UI-dependent details before phase 2 starts.

### Invocation and interpreter identity

Proposed invocation, from the repository root after compilation and authorization:

```sh
npm --prefix smoke run smoke -- \
  --build "/Applications/Visual Studio Code.app" \
  --suite python \
  --python-interpreter "/Users/jim/Desktop/genai/ide-tester/.venv/bin/python"
```

`--python-interpreter` is required for Python, rejected for other suites, and accepts an interpreter file path rather than a command with arguments or a PATH lookup. Resolve relative paths against the invocation working directory before any workspace/child-process change. Missing values, duplicates, invalid combinations and absent interpreter files must produce clear nonzero blocked results. Preflight checks only file presence (rejecting directories and broken links); it does not invoke the interpreter, inspect executable permissions or validate usability, version or environment identity. Any unusable interpreter discovered during the UI journey must yield a clear nonzero result at the observed stage. `qualify --suite python` is unsupported. Real Chat is unsupported for Python; the default `mock` option does not start a mock server or select Chat.

Proposed `preparePythonInterpreter` in `smoke/src/python-interpreter.ts` keeps three distinct values: original input, absolute invocation path, and canonical executable path. Resolve the canonical path through filesystem operations only. No preflight subprocess or identity probe is required. Never execute `hello.py` from the harness; the program's IDE execution supplies runtime identity evidence.

Preserving the invocation path matters for virtual environments whose executable symlinks resolve to a shared base Python. Pass that absolute path through the interpreter picker. Compare canonical runtime `sys.executable` with the canonical supplied path. Do not compare prefix/base-prefix or distinguish environments sharing the same canonical executable; that is outside the agreed identity check. Do not require a virtual environment or impose a Python-version eligibility check. Record the actual version from the IDE-run program and qualify only combinations exercised.

### Saved program and independent evidence

Proposed `smoke/src/python-evidence.ts` generates the standard-library-only source and validates execution evidence. Proposed `checkPython` in `smoke/src/python.ts` orchestrates the scenario through focused workbench operations, without embedding selectors or writing `hello.py` directly.

The program must:

1. Print the exact line `Hello, world!` and a separate structured identity line containing the unique current run ID, `sys.executable` and version. Version is reporting evidence, not an eligibility check; prefix/base-prefix evidence is not required.
2. Derive output paths from its own `__file__`, with evidence names unique to the run, inside the disposable workspace. Include the run ID, canonicalizable script path and interpreter identity in a versioned JSON payload.
3. Flush output, write evidence using an exclusive temporary file and atomic replacement into an initially absent completion destination, and print a unique completion line. Exceptions must remain errors; no success record after an earlier failure.

Before dispatch, require absence of the script and all evidence destinations, create/save the source exclusively through editor UI, compare exact saved UTF-8 bytes and SHA-256 independently, reopen and inspect it, and verify bytes again. Encode run IDs/paths as data when generating source, never by interpolating unescaped shell text. The harness reads evidence; only the IDE-run program writes it.

Select the absolute invocation path through **Python: Select Interpreter**, using the explicit-path flow even when discovery lists another Python. Verify the selection UI/status, keep `hello.py` active, establish a fresh owned terminal/baseline with no run markers, then invoke the extension's **Run Python File in Terminal** action exactly once. Command labels/IDs, picker flow and terminal targeting require installed-app verification in phase 1.

Passing requires all of: freshly observed greeting and identity/completion lines for this run in the targeted terminal after dispatch; exact independently verified saved source; and a regular non-symlink completion file inside the owned workspace with a valid complete schema, current run ID, correct script path and canonical `sys.executable` matching the supplied interpreter. These observations together establish smoke execution; no single marker, file, command echo or fixed delay is sufficient. Independent terminal-command exit status and shell success decorations are not required. Phase 1 must demonstrate the actual driver reading the fresh terminal evidence; a manual visual walkthrough or source inspection alone is insufficient. If that observation mechanism is unsupported, stop for developer review before implementation.

Use the never-before-used workspace/run ID, pre-dispatch absence, targeted terminal baseline, program output and completion markers together for freshness. Do not rely solely on timestamps, which can be coarse or manipulated. Reject stale IDs, wrong script/canonical interpreter, malformed or partial JSON, escaped/symlinked destinations, missing output, observed execution errors (including nonzero exit if exposed), interrupted runs and timeouts. Continue to verify the saved source has not changed before accepting results. Bound file size and observation polling; do not read unrelated terminal history or user files. The agreed contract does not independently detect an unobserved failure after all completion evidence is emitted; report this limitation rather than claiming verified zero exit. Confirming owned-process shutdown remains mandatory and separate from proving execution.
